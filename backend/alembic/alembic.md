# alembic/

Schema migrations. The database is never created by `create_all()` in the running app — every
environment gets its schema from `alembic upgrade head`.

| Path | Purpose |
|---|---|
| [env.py](env.py) | Loads settings, points Alembic at the same DB as the app, enables batch mode |
| [versions/](versions/versions.md) | One file per schema change, applied in order |
| [script.py.mako](script.py.mako) | Template for new revision files |
| [../alembic.ini](../alembic.ini) | Alembic config; `sqlalchemy.url` is intentionally blank |

## How the URL is resolved

`env.py` imports `app.core.config.get_settings()` and calls `config.set_main_option` with
`settings.sqlalchemy_url` (percent signs escaped for configparser). That means:

- `backend/.env` controls the target database for migrations *and* the app.
- Running `alembic` from the repo root or from `backend/` targets the same file.
- Tests never run migrations; they build schema from metadata against a temp file.

## Commands

```bash
uv run alembic upgrade head                        # apply everything
uv run alembic current                             # what is applied?
uv run alembic revision --autogenerate -m "add x"  # generate from model changes
uv run alembic downgrade -1                        # step back one revision
```

## Batch mode is mandatory here

SQLite cannot `ALTER COLUMN` or drop constraints in place. `render_as_batch=True` rewrites the
table under the hood. Never remove it from `env.py`.

## Review every autogenerated migration

Autogenerate compares metadata to the live DB, and it has sharp edges:

- It may emit `sqlmodel.sql.sqltypes.*` types **without** `import sqlmodel` — add the import.
- It does not infer data migrations (backfilling a new non-null column will fail on existing rows).
- It can propose dropping indexes it failed to reflect. If a drop looks unrelated, remove it.
- New non-nullable columns need `server_default` or a two-step migration.

## Initial schema

`versions/<rev>_initial_schema.py` creates `users`, `challenges`, and `submissions` with all
indexes, including the unique `submissions.image_sha256` and the composite cooldown index.
